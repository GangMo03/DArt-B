# 뉴욕시 Airbnb 숙소 가격 예측 분석 계획

**분석 목표:** 뉴욕시 Airbnb 숙소의 다양한 피처(feature)를 활용하여 숙소 가격(price)을 예측하는 최적의 모델을 구축한다.

**데이터셋:** `AB_NYC_2019.csv`

---

## 1단계: EDA (탐색적 데이터 분석)

EDA 단계에서는 데이터의 전반적인 구조와 통계적 특성을 파악하고, 잠재적인 문제점(결측치, 이상치)을 식별합니다.

### 1.1. 데이터 불러오기 및 기본 정보 확인
- **수행 내용:** Pandas 라이브러리를 사용하여 `AB_NYC_2019.csv` 파일을 데이터프레임으로 불러옵니다.
- **코드 수준:** `pandas.read_csv()` 함수를 사용합니다.
- **이후 과정:**
    - `.head()`: 데이터의 최상위 5개 행을 확인하여 각 컬럼의 데이터 형태를 직관적으로 파악합니다.
    - `.info()`: 각 컬럼의 데이터 타입(Dtype), Non-null 개수를 확인하여 결측치 존재 여부와 메모리 사용량을 파악합니다.
    - `.isnull().sum()`: 컬럼별 결측치 개수를 정확히 파악합니다.
- **선택 근거:** 데이터 분석의 가장 첫 단계로, 데이터의 원본 형태와 기본적인 구조를 파악해야 향후 처리 방향을 설정할 수 있습니다.

### 1.2. 기술 통계 분석
- **수행 내용:** 숫자형(numerical) 컬럼들의 핵심 통계량을 확인합니다.
- **코드 수준:** `.describe()` 메소드를 사용합니다.
- **확인 항목:**
    - `count`: 데이터 개수
    - `mean`, `std`: 평균, 표준편차를 통해 데이터의 중심 경향성과 변동성을 파악합니다.
    - `min`, `max`, `25%`, `50%`, `75%`: 사분위수를 통해 데이터의 분포와 이상치(outlier) 존재 가능성을 탐색합니다. 예를 들어 `price`의 `min` 값이 0이거나 `max` 값이 비정상적으로 높을 경우, 이상치 처리가 필요함을 암시합니다.
- **선택 근거:** 데이터의 분포를 수치적으로 이해하고, 향후 스케일링이나 이상치 제거 등의 전처리 필요성을 판단하는 기준이 됩니다.

### 1.3. 범주형 데이터 분석
- **수행 내용:** 범주형(categorical) 컬럼들의 고유값(unique value)과 그 빈도를 확인합니다.
- **코드 수준:** 각 범주형 컬럼에 대해 `.value_counts()` 메소드를 사용합니다.
- **분석 대상:** `neighbourhood_group`, `neighbourhood`, `room_type` 등.
- **선택 근거:** 범주형 데이터의 분포를 파악하여 특정 카테고리에 데이터가 편중되어 있는지 확인하고, 카디널리티(cardinality)가 매우 높은 피처(`neighbourhood` 등)의 처리 방안(예: Target Encoding, Feature Hashing)을 고민하는 근거를 마련합니다.

## 2단계: 데이터 전처리

EDA 단계에서 파악한 문제점들을 해결하고, 모델링에 적합한 형태로 데이터를 가공합니다.

### 2.1. 결측치 처리
- **수행 내용:** EDA에서 식별된 결측치를 각 컬럼의 특성에 맞게 처리합니다.
- **처리 방안:**
    - `reviews_per_month`: `number_of_reviews`가 0일 때 발생하는 `NaN`이므로, 0으로 채웁니다. (`.fillna(0)`)
    - `last_review`: 날짜 데이터이며, `reviews_per_month`와 상관관계가 높습니다. 예측 기여도가 낮을 것으로 판단되거나, 시계열 분석이 아닐 경우 모델의 복잡도를 낮추기 위해 컬럼 자체를 삭제(`drop`)하는 것을 우선 고려합니다.
    - `host_name`, `name`: 텍스트 데이터로, 결측치가 소수일 경우 해당 행을 제거하거나 "Unknown"과 같은 특정 값으로 채울 수 있습니다.
- **선택 근거:** 머신러닝 모델은 결측치를 처리할 수 없으므로 반드시 처리해야 합니다. 각 컬럼의 의미와 데이터 생성 맥락을 고려하여 논리적으로 가장 타당한 방식으로 결측치를 채워야 데이터 왜곡을 최소화할 수 있습니다.

### 2.2. 이상치 처리
- **수행 내용:** `price`와 같이 분포가 왜곡된 숫자형 데이터의 이상치를 처리합니다.
- **처리 방안:**
    - **IQR Rule:** 사분위수 범위를 이용하여 정상 범위를 정의하고, 이를 벗어나는 데이터를 이상치로 간주하여 제거하거나 대체합니다. (Q1 - 1.5*IQR, Q3 + 1.5*IQR)
    - **로그 변환(Log Transformation):** `price`와 같이 오른쪽으로 꼬리가 긴(right-skewed) 데이터는 `numpy.log1p` 함수를 적용하여 분포를 정규분포에 가깝게 만들어 이상치의 영향을 줄입니다.
- **선택 근거:** 이상치는 모델의 성능, 특히 선형 모델의 성능에 큰 영향을 미칠 수 있습니다. 로그 변환은 이상치의 영향을 줄이고 모델의 예측 안정성을 높이는 데 효과적입니다.

### 2.3. 피처 엔지니어링
- **수행 내용:** 기존 피처를 변환하거나 새로운 피처를 생성하여 모델의 성능을 향상시킵니다.
- **처리 방안:**
    - **범주형 피처 인코딩:**
        - `neighbourhood_group`, `room_type`: 카디널리티가 낮으므로 **원-핫 인코딩(One-Hot Encoding)**을 적용하여 이진(binary) 피처로 변환합니다. (`pandas.get_dummies` 또는 `sklearn.preprocessing.OneHotEncoder`)
        - `neighbourhood`: 카디널리티가 매우 높아 원-핫 인코딩 시 차원의 저주가 발생할 수 있습니다. **Target Encoding**이나 **Frequency Encoding**을 고려하거나, 초기 모델에서는 `neighbourhood_group`으로 대체하고 제외할 수 있습니다.
    - **불필요한 피처 제거:** `id`, `host_id`, `host_name`, `name`, `last_review` 등 식별자이거나 직접적인 예측 가치가 낮은 텍스트/날짜 피처는 모델의 복잡도를 줄이기 위해 제거합니다. (`.drop()`)
- **선택 근거:** 모델은 수치 데이터를 입력으로 받으므로 범주형 데이터의 인코딩은 필수적입니다. 피처의 특성(카디널리티)에 맞는 인코딩 방식을 선택해야 하며, 예측에 도움이 되지 않는 피처를 제거하여 모델을 더 가볍고 빠르게 만듭니다.

## 3단계: 데이터 시각화

EDA와 전처리 결과를 바탕으로, 피처 간의 관계와 데이터의 패턴을 시각적으로 탐색하여 깊은 인사이트를 얻습니다.

### 3.1. 타겟 변수(`price`) 분포 시각화
- **수행 내용:** `price` 컬럼의 분포를 시각화합니다.
- **코드 수준:** `seaborn.histplot` 또는 `displot`을 사용하여 히스토그램과 커널 밀도 추정(KDE) 그래프를 그립니다. 로그 변환 전/후를 비교하여 전처리 효과를 확인합니다.
- **선택 근거:** 타겟 변수의 분포가 정규성을 띠는지 확인하는 것은 선형 모델의 성능에 중요합니다. 시각화를 통해 분포의 왜곡 정도를 직관적으로 파악할 수 있습니다.

### 3.2. 주요 피처와 타겟 변수 간 관계 시각화
- **수행 내용:** 주요 범주형/숫자형 피처와 `price` 간의 관계를 시각화합니다.
- **코드 수준:**
    - **범주형 vs `price`:** `seaborn.boxplot` 또는 `violinplot`을 사용하여 `neighbourhood_group`이나 `room_type`에 따른 `price`의 분포를 비교합니다.
    - **숫자형 vs `price`:** `seaborn.scatterplot`을 사용하여 `number_of_reviews`, `availability_365` 등과 `price`의 관계를 확인합니다.
- **선택 근거:** 어떤 피처가 가격에 중요한 영향을 미치는지 시각적으로 탐색하고, EDA 단계의 가설을 확인하는 과정입니다.

### 3.3. 피처 간 상관관계 분석
- **수행 내용:** 숫자형 피처들 간의 상관관계를 분석합니다.
- **코드 수준:** `pandas.DataFrame.corr()`로 상관계수 행렬을 계산하고, `seaborn.heatmap`으로 시각화합니다.
- **선택 근거:** 피처 간 높은 상관관계(다중공선성)는 선형 모델의 회귀 계수 추정을 불안정하게 만들 수 있습니다. 히트맵을 통해 이러한 관계를 한눈에 파악하고, 필요시 피처 선택의 근거로 활용합니다.

## 4단계: 가설 검정

시각화 및 EDA를 통해 세운 잠정적인 가설을 통계적으로 검증합니다.

### 4.1. 가설 설정
- **가설 1:** "맨해튼(`Manhattan`) 지역의 숙소 평균 가격은 브루클린(`Brooklyn`) 지역의 숙소 평균 가격보다 유의미하게 높을 것이다."
- **가설 2:** "`Entire home/apt` 타입의 숙소 평균 가격은 `Private room` 타입의 숙소 평균 가격보다 유의미하게 높을 것이다."

### 4.2. 검정 방법 선택 및 수행
- **수행 내용:** 두 독립적인 그룹 간의 평균을 비교하므로 **독립표본 T-검정(Independent Samples T-test)**을 수행합니다.
- **코드 수준:** `scipy.stats.ttest_ind` 함수를 사용합니다.
- **선택 근거:** T-검정은 두 집단의 평균 차이가 통계적으로 유의미한지를 검증하는 대표적인 통계 분석 방법입니다.

### 4.3. 결과 해석
- **수행 내용:** 검정 결과로 나온 p-value를 확인합니다.
- **해석:** p-value가 유의수준(e.g., 0.05)보다 작으면 귀무가설(두 그룹의 평균이 같다)을 기각하고, 대립가설(두 그룹의 평균이 다르다)을 채택합니다. 이를 통해 가설이 통계적으로 유의미함을 입증합니다.

## 5단계: 모델링

전처리가 완료된 데이터를 사용하여 가격 예측 모델을 구축하고 평가합니다.

### 5.1. 데이터 분할
- **수행 내용:** 피처(X)와 타겟(y, `price`)을 분리하고, 전체 데이터를 훈련(train) 데이터와 테스트(test) 데이터로 분할합니다.
- **코드 수준:** `sklearn.model_selection.train_test_split` 함수를 사용합니다. (e.g., 80% train, 20% test)
- **선택 근거:** 모델을 훈련시킨 데이터로 평가하면 과적합(overfitting)된 결과가 나옵니다. 모델이 보지 못한 새로운 데이터(테스트 데이터)로 성능을 평가해야 일반화 성능을 객관적으로 측정할 수 있습니다.

### 5.2. 모델 선택 및 학습
- **수행 내용:** 여러 머신러닝 모델을 선택하여 훈련 데이터로 학습시킵니다.
- **모델 후보:**
    1. **선형 회귀 (Linear Regression):** 가장 기본적인 회귀 모델로, 성능의 기준선(baseline)을 설정하기 위해 사용합니다. (`sklearn.linear_model.LinearRegression`)
    2. **랜덤 포레스트 회귀 (RandomForest Regressor):** 여러 결정 트리를 결합한 앙상블 모델로, 비선형 관계를 잘 학습하고 일반적으로 높은 성능을 보입니다. (`sklearn.ensemble.RandomForestRegressor`)
    3. **그래디언트 부스팅 회귀 (GradientBoosting Regressor):** 이전 트리의 오차를 보완하며 순차적으로 트리를 만드는 앙상블 모델로, 랜덤 포레스트보다 더 높은 성능을 기대할 수 있습니다. (`sklearn.ensemble.GradientBoostingRegressor` 또는 `XGBoost`, `LightGBM`)
- **선택 근거:** 단순한 모델부터 복잡한 모델까지 다양하게 시도하여 문제에 가장 적합한 모델을 찾습니다. 선형 모델로 해석력을 얻고, 트리 기반 앙상블 모델로 예측 성능을 극대화하는 전략을 사용합니다.

### 5.3. 모델 평가
- **수행 내용:** 테스트 데이터에 대한 모델의 예측 성능을 평가합니다.
- **평가 지표:**
    - **MAE (Mean Absolute Error):** 예측 오차의 절댓값 평균. 실제 가격과의 차이를 직관적으로 해석하기 좋습니다. (`sklearn.metrics.mean_absolute_error`)
    - **MSE (Mean Squared Error):** 예측 오차의 제곱 평균. 큰 오차에 더 큰 페널티를 부여합니다. (`sklearn.metrics.mean_squared_error`)
    - **R² (결정 계수):** 모델이 타겟 변수의 분산을 얼마나 잘 설명하는지를 나타냅니다. 1에 가까울수록 좋습니다. (`sklearn.metrics.r2_score`)
- **선택 근거:** 각 평가 지표는 모델의 성능을 다른 관점에서 보여주므로, 종합적으로 판단해야 합니다. 로그 변환된 `price`로 예측했다면, `numpy.expm1`을 사용하여 원래 스케일로 되돌린 후 평가를 수행해야 합니다.

### 5.4. 하이퍼파라미터 튜닝
- **수행 내용:** 가장 성능이 좋은 모델(e.g., 랜덤 포레스트)을 대상으로 최적의 하이퍼파라미터를 탐색합니다.
- **코드 수준:** `sklearn.model_selection.GridSearchCV` 또는 `RandomizedSearchCV`를 사용하여 최적의 `n_estimators`, `max_depth` 등을 찾습니다.
- **선택 근거:** 하이퍼파라미터 튜닝은 모델의 잠재 성능을 최대한으로 이끌어내기 위한 필수적인 과정입니다. 이를 통해 과적합을 방지하고 일반화 성능을 높일 수 있습니다.
